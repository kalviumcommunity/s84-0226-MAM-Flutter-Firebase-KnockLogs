# Contributing to KnockLogs

Thanks for being interested in contributing to KnockLogs. This project is built by a passionate team of developers dedicated to creating a robust access control system. Your contributions help make it better.

## Getting Started

Before you start, familiarize yourself with the project structure and the technologies we use:
- Flutter 3.9.2+
- Firebase (Firestore, Auth, Storage)
- Provider for state management

## Code Standards

- Follow Dart style guide and Flutter best practices
- Use meaningful variable and function names
- Write self-documenting code with minimal comments
- Format code using `dart format`
- Run `flutter analyze` before committing
- Ensure no compilation errors before submitting

## Commit Guidelines

- Use clear, descriptive commit messages
- Reference issues in commit messages: `Fixes #123`
- Keep commits focused on a single feature or fix
- Avoid combining multiple unrelated changes
- Test locally before pushing

## Pull Requests

1. Create a feature branch: `git checkout -b feature/your-feature`
2. Make your changes and test thoroughly on all platforms
3. Push to your branch: `git push origin feature/your-feature`
4. Submit a pull request with a detailed description of changes
5. Ensure all checks pass before requesting review
6. Link related issues

## Testing

- Test features on all supported platforms (Android, iOS, Web, Windows, macOS, Linux)
- Verify Firestore queries work without errors
- Test with both light and dark themes
- Document any new Firebase collections or indexes
- Check for memory leaks and performance issues

## Code Review Process

- Address feedback promptly and professionally
- Ask for clarification if feedback is unclear
- Request re-review after making changes
- Merge only after approval from maintainers

## Reporting Issues

- Include clear description of the problem
- Provide steps to reproduce
- Specify platform and Flutter version
- Include relevant error logs and screenshots
- Check if issue already exists before reporting

## Development Tips

- Use `flutter pub get` to install dependencies
- Use `flutterfire configure` if adding Firebase features
- Keep state management centralized using Provider
- Follow the existing folder structure
- Test edge cases and error scenarios
